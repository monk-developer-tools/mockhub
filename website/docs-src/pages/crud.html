In Stubs, choose CRUD resource and name it, e.g. customers. MockHub creates one stub that handles:

RequestDoes
GET /customerslist; filter with ?city=London, sort with _sort=name&_order=desc, page with _limit and _offset; the total is in X-Total-Count
GET /customers/{id}one record, or 404
POST /customerscreate; the id is generated (1, 2, 3 or a UUID) unless you send one; 201 with a Location header
PUT /customers/{id}replace
PATCH /customers/{id}merge fields; null removes one
DELETE /customers/{id}delete; 204

Records are kept per project in /data/mockhub/data, survive restarts and are included in backups. The Data tab lists them and lets you add, edit, delete or clear them. For custom stateful flows, the WireMock state extension is included too (its state lives in memory).
