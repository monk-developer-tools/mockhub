In Stubs, choose CRUD resource and name it, e.g. customers. MockHub creates one stub that handles:

RequestDoes
GET /customerslist; filter, sort and page it (see below); the total is in X-Total-Count
GET /customers/{id}one record, or 404
POST /customerscreate; the id is generated (1, 2, 3, a UUID, or 10 random letters and digits such as k3x9q0zb7m) unless you send one; 201 with a Location header
PUT /customers/{id}replace
PATCH /customers/{id}merge fields; null removes one
DELETE /customers/{id}delete; 204

Filter, sort and page

Add these to a list request, e.g. GET /products?price[gte]=10&brand.country=UK&sort=-price&page=2&size=20:

WriteGives
city=Londonrecords whose city is exactly London
status=paid&status=shippedeither value: a repeated field means OR
price[gte]=10, [gt], [lte], [lt]comparisons; numbers compare as numbers, other values as text, so ISO dates work too
stock[ne]=0not equal, including records without the field
brand.country=UKa nested field; on a list such as tags=office, any item matches
active=truebooleans and numbers match their text, so price=180 finds 180.0
sort=-price,namesort by several fields; a minus sorts that field high to low
page=2&size=20pages from 1; size defaults to 20
limit=10&offset=30the same, counted in records

Filters combine with AND. An unknown operator such as price[between]=1 or a bad number such as page=0 gets a 400 with a message. The json-server style _sort=name&_order=desc, _limit and _offset still work. Because sort, page, size, limit and offset control the list, you can't filter on fields with those names.

Limits and errors

A resource keeps up to 10,000 records. When a new one would go past that, the oldest record is removed, so a long test run never fills the disk. Change the number with MOCKHUB_MAX_RECORDS, or set 0 for no limit.

Errors are JSON with a message and a stable code, such as invalid_json_body for a body that doesn't parse or not_found for an unknown id. The error reference lists them all.

Records are kept per project in /data/mockhub/data, survive restarts and are included in backups. The Data tab lists them and lets you add, edit, delete or clear them. For custom stateful flows, stubs can also record state, which is stored the same way.
