In a project, open Assistant and describe what you need, or paste an OpenAPI spec, a WSDL or curl commands. The assistant reads the stubs, searches the request history, reads recent callouts and stages changes. It can set up webhooks and wait-for-callout stubs from a sentence, such as “after POST /payments, call the callbackUrl from the request 2 seconds later with status SETTLED”, and it can explain and fix a failing one. You review each one as a diff and apply or discard it, so nothing changes until an editor applies it. Viewers can draft changes but not apply them.

In a stub's Then call section, Ask the assistant takes a description of a webhook for that stub. In the Callouts tab, Ask the assistant to fix it sends it a failed callout.

For a single response, select Generate with AI next to a stub's body. Describe it, check the result and select Use this body. This needs the editor role.

When a templated body doesn't render, Try it in the stub editor shows the template error in plain words instead of the server's error page, with Fix with AI. It sends the template, the error and the request you tried, and puts the corrected template in the body; check it, save, and send again. This also needs the editor role, and works on the form editor's JSON, XML and text bodies. From a script, POST /__admin/mockhub/api/projects/{id}/ai/template/fix with {"template", "error", "request"} returns {"template"}.

To use your own coding agent instead, such as Claude Code, Cursor or Codex, connect it over MCP. Changes from agents with a review token appear in the same tab.

The conversation, the project's stubs and, when needed, recent requests go to the provider you configure. Choose one your organisation allows, or run models yourself behind LiteLLM.
