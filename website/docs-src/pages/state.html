Scenarios move one flow between named states. When a mock needs to remember data, such as the items in a cart or the status of an order, use recorded state. A stub saves values under a context name, and any later stub reads them back in its response.

MockHub includes the WireMock state extension and keeps its state per project: it survives restarts, travels in backups and is deleted with the project.

Record state

Add a recordState listener to the stub that changes state. This one adds an item to cart 7 when you POST /shop/carts/7/items:

{
  "request": { "method": "POST", "urlPathTemplate": "/carts/{id}/items" },
  "response": { "status": 201 },
  "serveEventListeners": [{
    "name": "recordState",
    "parameters": {
      "context": "cart-{{request.path.id}}",
      "state": { "status": "open" },
      "list": { "addLast": { "sku": "{{jsonPath request.body '$.sku'}}" } }
    }
  }]
}

state sets named properties. list keeps an ordered list of objects: addLast or addFirst adds one. A deleteState listener with the same context removes the whole context, or with list removes an item: deleteFirst, deleteLast, deleteIndex or deleteWhere.

Read it back

Turn on templating and use the state helper:

{{state context=(join 'cart-' request.path.id '') property='status' default='none'}}
{{state context=(join 'cart-' request.path.id '') property='listSize' default='0'}}

After two items, GET /shop/carts/7 answers open 2. With no state yet it answers the defaults. See the extension's README for list access, matching on state and the full set of options.

See and change it

Open the project's Data tab and choose State → Contexts. Each context shows its properties, list size, how often it changed and when. Editors can:

  • Edit a context as JSON, e.g. set status to paid to test the next step of a flow.
  • Add context to prepare state before a test runs.
  • Delete one context, or Clear them all, to start a test from scratch.

Stubs see your changes straight away. Values are stored as text, as the extension does. A project keeps up to 10,000 contexts (MOCKHUB_MAX_RECORDS); past that, the one changed longest ago is removed.

From a script or test

RequestDoes
GET /__admin/mockhub/api/projects/{id}/stateevery context of the project
PUT …/state/context?name=cart-7set a context from {"properties": {...}, "list": [...]}
DELETE …/state/context?name=cart-7delete one context; 404 if there is none
DELETE …/statedelete all of the project's state

Reading needs the viewer role on the project; changing needs editor. Context names are shared across projects, so give them a project prefix if two projects might use the same one. State is written by calls to a project's own base path; the public instant mocks can't record state.
