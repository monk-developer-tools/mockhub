Environments let one project answer as dev, qa or staging without copying it. Each environment has its own variables, stubs read them with {{env 'name'}}, and a stub can be limited to some environments. One environment is active; a caller can ask for another with a header.

Set them up

Open the project's Settings tab and find Environments. Select Add environment for each one, give it a name of lowercase letters, digits and dashes, and add variables such as baseUrl or tenantId. Pick the active one and select Save environments. Once a project has environments, its header shows the active one; editors switch it there. A project can have 10 environments with 100 variables each.

Read variables in answers

Turn on templating in the stub and use {{env 'baseUrl'}} for a variable's value, or {{env}} for the environment's name. A variable an environment doesn't have renders as empty.

{
  "paymentUrl": "{{env 'baseUrl'}}/payments/{{request.path.id}}",
  "environment": "{{env}}"
}

Different answers per environment

In the stub editor, tick environments under Only in environments; with none ticked the stub answers in every environment. For example, a stub that declines cards only in qa, with priority 1, wins over the stub that approves everywhere. Behind the checkboxes is a plain WireMock header matcher, so snapshots, Git sync and exports keep it:

"request": {
  "method": "POST",
  "urlPath": "/charges",
  "headers": { "X-MockHub-Environment": { "matches": "qa|staging" } }
}

Choose an environment per call

Calls answer as the active environment. To ask for another, send the X-MockHub-Environment header, such as X-MockHub-Environment: qa; a name the project doesn't have falls back to the active one. MockHub writes the chosen name into that header before matching, so it shows in the request history and the Inspect tab.

curl -X POST https://mocks.example.com/pay/charges -H 'X-MockHub-Environment: qa'

Paths are under /__admin/mockhub/api. Viewers can read environments; changing them needs the editor role. Over MCP, agents use get_environments, set_environments and switch_environment. Environments are not part of snapshots or Git sync yet; the stubs that use them are. They apply to HTTP calls; gRPC calls answer without one.
