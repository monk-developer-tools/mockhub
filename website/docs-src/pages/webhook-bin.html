A webhook bin is a URL that records every request sent to it and shows each one beside the answer it got. It needs no account. Use the free webhook catcher on the demo, or turn on MOCKHUB_PUBLIC_TOOLS on your own server (see Public tools).

What a bin keeps

Send any method to /__public/bins/{id} or any path under it. The bin keeps every request with its method, path, query, headers, body (up to 64 KB) and the answer it sent back: status, headers, body, how long it took and what produced it. There is no request count limit. A bin holds up to 50 MB in files of 10 MB; past that it drops its oldest file. The list loads 100 requests at a time, and Load older requests pages back.

When a request names its event, the bin shows it as a badge. It reads the X-GitHub-Event, X-Gitlab-Event, X-Event-Key, X-Shopify-Topic, X-Webhook-Event and X-Event-Type headers, then the JSON fields type, event, event_type, eventType, topic and action.

Only the browser that created the bin holds its token. Copy private link gives a link with the token in it that opens the bin in any browser; keep it to yourself. A bin is deleted 24 hours after its last request.

Dynamic answers

Both the default answer and every rule answer can be built from each request. Pick from Insert a dynamic value, or write template expressions yourself, and tick Fill in dynamic values:

{
  "order": "{{jsonPath request.body '$.id'}}",
  "currency": "{{request.query.currency}}",
  "path": "{{request.path}}",
  "at": "{{now}}"
}

Preview shows the answer built from the latest request the bin received, or from a sample request when there is none yet. Paths are the part under the bin, like /orders. The Dynamic answer starting point gives a rule that does this, with a new X-Request-Id header each time.

Rules

Rules answer requests before routing does. The first enabled rule that matches answers; drag rules to change the order, untick one to skip it, or switch Rules on off to skip them all. A rule matches a method (or any) and all of its conditions:

Look atNameTests
Pathnone, the path under the bin, like /paymentsequals, starts with, contains, matches regex, is present
Query parameterthe parameter
Headerthe header, any case
Body textnone
JSON fielda path like $.data.object.status or $.items[0].id

An answer has a status, a delay up to 15 seconds, headers and a body. Tick Fill in dynamic values to render the body and headers as a template, for example {{jsonPath request.body '$.id'}}, {{now}} or {{fake 'Name.fullName'}}. Give a rule up to five answers with weights to make a flaky endpoint: weights 3 and 1 answer the first three times in four.

The starting points fill the editor with a common rule: fail with 500, answer after 5 seconds, match one event type, echo the body back and fail one in four. A bin holds up to 50 rules of up to 10 conditions each.

When the server has an AI provider, Draft with AI turns a description such as "answer 402 with the payment id when the event is payment.failed" into a rule. It needs a MockHub sign-in: anonymous visitors don't get AI drafts. Each user gets 10 drafts an hour. The draft opens in the editor and is saved only when you save it.

Routing

Routing decides what answers a request no rule matched.

  • Default answer: the bin's reply, 200 {"ok":true} unless you change it.
  • Forward: the request goes on to a target plus an optional path prefix plus the path under the bin, with its query, headers and body, and the target's answer goes back to the sender. You can add headers to every request and every answer, and skip TLS certificate checks. Only public addresses are allowed; the target has 15 seconds and 1 MB.
  • Local tunnel: the request reaches a service on your machine. Run the command the page shows, which uses the MockHub tunnel client with the bin's own key: 
    java -jar mockhub.jar tunnel --server https://mockhub.devops-monk.com \
  --token bin_{id}_{token} --name bin-{id} --to http://localhost:3000
    The bin's key opens only the tunnel named bin-{id}, and no other key can use a name that starts with bin-. The page shows whether the tunnel is connected.

When forwarding or the tunnel fails, the sender gets 502 with a JSON error, and the request shows Forward failed or Tunnel failed.

From a script

curl -X POST https://mockhub.devops-monk.com/__public/bins
curl https://mockhub.devops-monk.com/__public/inspect/{id} -H 'X-Bin-Token: {token}'
curl -X PUT https://mockhub.devops-monk.com/__public/inspect/{id}/rules -H 'X-Bin-Token: {token}' \
  -H 'Content-Type: application/json' -d '{"rulesEnabled": true, "rules": [{
    "name": "Failed payments", "method": "POST",
    "conditions": [{"target": "json", "key": "$.type", "op": "equals", "value": "payment.failed"}],
    "answers": [{"status": 402, "delayMs": 500, "body": "{\"id\": \"{{jsonPath request.body '"'"'$.id'"'"'}}\"}", "template": true}]}]}'

Every endpoint is listed under Public tools.
