Add conditions on query parameters, headers, cookies and the body. Every condition must match. Body matchers include JSON equals (optionally ignoring extra fields and array order), JSONPath (for example $[?(@.amount > 1000)]), XML equals, XPath, contains and regex.

The method is GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS, QUERY or Any. QUERY is the new HTTP method for a safe read that carries a body, such as a search with filters; match its body like a POST's. An OpenAPI 3.2 file's query operations import as QUERY stubs.

Which stub wins

When several stubs match a request, WireMock tries them in order and the first one answers: the lowest priority number first (1 is highest, stubs without one count as 5), and among equal priorities the newest stub first. Open the Stubs tab and click Show matching order to see that order as a numbered list, with what answers when nothing matches: WireMock's 404, or the project's default response.

Editors can drag a stub, or use its arrows, to change the order, then Save order. MockHub rewrites the priorities as 10, 20, 30… so the order is explicit and stays the same after imports and restarts. Put specific stubs, like an error for one id, above general ones, like a path template or a regex.

The patterns teams use most, like magic test ids for error paths, a regex on one body field with a low-priority fallback, filters inside arrays, one stub for every environment and proxying chosen ids to a real service, are explained step by step in Matching patterns from real projects and installed together as the Matching patterns example.
