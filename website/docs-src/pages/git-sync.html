Link a project to a folder in a Git repository to keep its mocks next to your code. Push writes the project as one file per stub and makes a commit, so mock changes can be reviewed in pull requests and traced in git log. Pull shows what the repository would change and then applies it, after saving a safety snapshot. Open a project's Snapshots tab; the Git panel is at the top.

What goes in the repository

mockhub/orders/                 the folder you choose
  mockhub.json                  runtime behaviour, API key header and stub order
  mappings/get-order-7f3a9c21.json   one WireMock stub per file
  __files/invoice.pdf           response files as they are
  • File names come from the stub name, or its method and path, plus the first 8 characters of its id.
  • Push rewrites only mockhub.json, mappings/ and __files/ in the folder. Everything else in the repository stays, so the folder can live inside a service's own repository.
  • Pull also reads a plain WireMock folder without mockhub.json: each file in mappings/ can hold one stub or {"mappings": [...]}. Set the folder to the one that holds mappings/, or leave it empty for the repository root.
  • Like snapshots, the repository holds no CRUD records, request history or API key value.

Link a repository

Select Link a repository and give the HTTPS URL, such as https://github.com/acme/mocks.git, a branch (default main), the folder and an access token that can read and write the repository: a fine-grained GitHub token with Contents: read and write, a GitLab project token with write_repository, or a Bitbucket app password with your username. The token is encrypted with the server's secret key and never shown again. A branch that doesn't exist yet is made on the first push. SSH URLs aren't supported.

Linking, changing and unlinking need the manager role in the project's team; pushing and pulling need the editor role. Repositories on private or local addresses are refused unless an admin sets MOCKHUB_GIT_ALLOW_PRIVATE=true, which also allows file: URLs.

Push and pull

Type a commit message, or keep the suggested one, and select Push. The commit is authored by you, or by the token's name when an agent pushes. When nothing changed, no commit is made. If someone pushed to the branch at the same moment, MockHub asks you to push again.

Select Pull to see every stub the repository would add, change or remove, plus file and runtime changes, then Pull into this project. The project's state is saved as a safety snapshot first, so you can restore it from the list below.

From scripts and agents

CallDoes
GET /projects/{id}/gitthe link, without the token, with the last push and pull
PUT /projects/{id}/git{"url", "branch", "folder", "username", "token"}; leave out the token to keep the saved one
DELETE /projects/{id}/gitunlink; the repository keeps its files
POST /projects/{id}/git/push{"message"}; returns the commit and whether anything changed
GET /projects/{id}/git/previewwhat a pull would change, in the snapshot compare format
POST /projects/{id}/git/pullapplies the repository and returns the safety snapshot

Paths are under /__admin/mockhub/api. Over MCP, agents use git_preview, git_push and git_pull. In CI, push from a pipeline after changing mocks, or pull into a fresh MockHub at the start of a test run so it serves exactly what the repository holds.
