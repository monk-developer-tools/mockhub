A snapshot saves a project's mocks at one moment, so you can see what changed since and go back. Take one before a release, a demo or a risky change, compare it with now, and restore it if something breaks. You can also pull one project's mocks into another, for example dev into qa, and move a snapshot between servers as a file. Open a project's Snapshots tab.

What a snapshot holds

IncludedNot included
  • Every stub, in matching order, with its on or off state
  • CRUD resource definitions
  • Response files
  • Runtime behaviour: delays and faults, the default response, rate limits, CORS and the IP allow list
  • The API key header name
  • Records stored by CRUD resources
  • Request history and callouts
  • The API key value, or any other secret
  • The project's name, base path, team and members

Records are left out on purpose: they're test data that changes as tests run, and restoring stubs shouldn't undo a test's writes. Secrets are left out so a snapshot file is safe to share.

Take and compare

Select Take snapshot, give it a name such as release 1.4 and, if you like, a purpose. The list shows who took each one, when, and what it holds. Compare with now lists every stub that was added, changed, removed or moved in the matching order since then, with a before-and-after diff for each, plus changed response files and runtime behaviour. Tick two snapshots and select Compare selected to compare them with each other. Viewers can compare and download; taking, restoring, uploading, pulling and deleting need the editor role.

Restore

Select Restore on a snapshot. MockHub shows exactly what restoring changes and asks you to confirm. It then saves the current state as a safety snapshot named Before restoring “release 1.4”, puts back the stubs in their order, the response files and the runtime behaviour, and removes stubs and files the snapshot doesn't have. Stored records and the API key value stay as they are. If the restore was a mistake, restore the safety snapshot.

A project keeps its last 10 safety snapshots and up to 50 of your own. Deleting a project deletes its snapshots.

Pull from another project

Select Pull from a project to replace this project's mocks with another project's, as they are now or as a saved snapshot. MockHub shows the difference first and saves a safety snapshot before it changes anything. URLs move to this project's base path, so stubs from /shop-dev answer at /shop-qa, and response files are copied across. Stubs get ids of their own in this project; pulling the same source again keeps them, so the diff shows only real changes. You can pull from any project you can view, and only into one you can edit. A token limited to some projects can't pull from others.

Download and upload

The download button saves a snapshot as one JSON file, with response files inside it. Upload adds such a file to a project's list without changing anything; compare it, then restore it. Use files to keep a known-good state in your repository, or to move a project's mocks between MockHub servers. MockHub checks a file before it accepts it: it must be a mockhub-snapshot file, hold at most 5,000 stubs, have valid stubs and file names, and no file larger than 10 MB.

{
  "format": "mockhub-snapshot",
  "version": 1,
  "name": "release 1.4",
  "purpose": "Contract agreed with the mobile team",
  "createdAt": "2026-11-03T10:15:00Z",
  "createdBy": "Alex Morgan",
  "project": { "id": "58b5108a", "name": "Bookshop" },
  "settings": { "runtime": { … }, "apiKeyHeader": "X-API-Key" },
  "stubs": [ … ],
  "files": { "prices.csv": "aXNibixwcmljZQ…" }
}

Stub URLs in the file are relative to the project's base path, and files are base64.

Assistant and agents

Ask the AI assistant to “take a snapshot called before-retries, then add retry stubs” or to “restore the release 1.4 snapshot”. Both arrive as staged changes you apply, and a snapshot is always taken before the other changes in the same batch. Agents over MCP can list, take, compare and restore snapshots and pull from another project. A review-mode token stages snapshots and restores for a person to apply, and can't pull.

API

# take a snapshot before deploying new stubs from CI
curl -X POST -H "Authorization: Bearer $MOCKHUB_TOKEN" $HUB/__admin/mockhub/api/projects/$ID/snapshots \
  -d '{"name":"before build 412","purpose":"CI deploy"}'

# what changed since then
curl -H "Authorization: Bearer $MOCKHUB_TOKEN" "$HUB/__admin/mockhub/api/projects/$ID/snapshots/compare?from=$SNAP&to=current"

# copy dev into qa
curl -X POST -H "Authorization: Bearer $MOCKHUB_TOKEN" $HUB/__admin/mockhub/api/projects/$QA/pull -d "{\"from\":\"$DEV\"}"

Taking, uploading, restoring, deleting and pulling appear in the audit log.

Snapshots and backups

Snapshots are stored in /data/mockhub/snapshots, one folder per project, so a copy of the data volume includes them. The backup file from Backup & restore doesn't: it holds the projects as they are now. To keep a particular version with a backup, download that snapshot as a file.
