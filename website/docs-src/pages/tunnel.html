Just need a public URL for localhost? The free local tunnel page on the demo sets one up through a webhook bin and gives you the command to run, with a live log of every request.

A tunnel lets a mock reach a service running on your own machine. Proxy stubs and callouts that target tunnel://laptop/path go to MockHub, through the tunnel, to whatever you run on localhost. Webhooks from a shared MockHub reach the code you're debugging, and a proxy stub can pass some calls to your local build.

Start a tunnel

  1. Create an access token with the editor role: your avatar → Access tokens → New token. See Access tokens.
  2. On your machine, with the same mockhub.jar the server runs (Java 17 or later):
export MOCKHUB_TOKEN=mh_...
java -jar mockhub.jar tunnel --server https://mockhub.example.com --name laptop --to http://localhost:3000
OptionMeaning
--serverMockHub's address, or MOCKHUB_URL
--tokenYour access token, or MOCKHUB_TOKEN. Prefer the environment variable so the token stays out of shell history.
--nameThe tunnel name: 1 to 40 lowercase letters, digits and dashes. Stubs reach it as tunnel://<name>.
--toThe local service that answers, such as http://localhost:3000
--workersRequests handled at the same time, 1 to 20 (default 4)

The tunnel prints one line per request, such as POST /hooks -> 204 (12 ms). Stop it with Ctrl+C. It only makes outgoing calls to MockHub, so it works from behind a firewall or NAT and through nginx, with no port to open.

Use it in a stub

  • Proxy: set the response type to Proxy and Forward to to tunnel://laptop/api. A call to /pay/orders/7 reaches http://localhost:3000/api/orders/7 on your machine, query string included.
  • Then call and Wait for callout: use tunnel://laptop/hooks as the URL. Retries, connections and the Callouts tab work as for any other URL.
{
  "request": { "method": "POST", "urlPath": "/charges" },
  "response": { "status": 201 },
  "serveEventListeners": [{
    "name": "mockhub-callout",
    "parameters": { "method": "POST", "url": "tunnel://laptop/hooks", "body": "{\"event\":\"charge.created\"}" }
  }]
}

Rules and limits

RuleDetail
Who can open oneAn access token from someone with the editor role in a team. Review-only tokens can't. A name belongs to whoever opened it until the tunnel closes; anyone else gets 409.
Which projects can use itOnly projects the tunnel owner can edit, and only those the token is scoped to. Others get 403, so nobody can send traffic to your machine from a project you can't edit.
Size and loadRequests and answers up to 5 MB each, 20 requests waiting per tunnel, 5 tunnels per user. Each request waits up to 30 seconds.
When it's downA proxy stub that uses a tunnel nobody runs answers 502, with the reason in the X-MockHub-Tunnel-Error header. If the local service can't be reached or takes longer than 28 seconds, the tunnel answers 502 with the reason in the body. Callouts record the same errors in the Callouts tab.
ClosingWhen the command stops, the tunnel shows as offline about a minute later and keeps its name for you. Revoking its token, or Close in the Tunnels tab, closes it at once, frees the name and stops the command.

See your tunnels

Your avatar → Tunnels lists your tunnels with their status, request and failure counts and traffic, and shows the start command. Admins see everyone's tunnels and their owners.

The tunnel uses HTTP long polling: the command keeps a few requests open to /__admin/mockhub/tunnel/<name>/next and MockHub answers one when a stub sends something through. If your reverse proxy times out requests in under 30 seconds, raise the limit for that path (for nginx, proxy_read_timeout 60s).
