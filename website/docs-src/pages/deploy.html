AWS ECS with Terraform

The repository's deploy/terraform module creates a Fargate service, an encrypted EFS volume for /data, an Application Load Balancer with optional HTTPS, and the IAM and security groups around them.

cd deploy/terraform
cp terraform.tfvars.example terraform.tfvars
terraform init && terraform apply

Running on a platform you already have, such as ECS with your own Terraform modules? Point the load balancer health check at /__admin/health, give /data a persistent volume (EFS on Fargate), and run one task: MockHub keeps its data in files, so scale up rather than out. For deploys without a gap, see below. To attach an APM agent, mount it and add -javaagent:/path/agent.jar to JAVA_TOOL_OPTIONS.

Deploys without a gap

MockHub keeps one writer for its data folder. With MOCKHUB_HA=true a new server can take over from a running one on the same folder instead of waiting for it to stop: it asks the running server to hand over, that server finishes its writes and exits, and the new one takes the lock and starts. In our two-process test on one machine the pause between the last answer from the old server and the first from the new one was under a second.

  • On AWS with the Terraform module, set handover_deploys = true. ECS then starts the new task before stopping the old one, passes MOCKHUB_HA, and the load balancer checks health every 5 seconds, so expect a pause of about the time it takes the load balancer to mark the new task healthy (two checks). Turn it on in a deploy after the image already supports it: a running server from an older image can't hand over, and the new task gives up after MOCKHUB_HA_WAIT_SECONDS (120) and the deploy rolls back.
  • Try it on a test stack first and watch one deploy: the old task should log A new MockHub asked to take over and the new one Took over after … ms.
  • Docker or a VM: start the new container on the same data folder and another port, switch the proxy to it once it answers /__admin/health, and the old one stops by itself.

Handover is not more capacity: one server answers at a time. If a server crashes instead of handing over, the lock is freed when its process ends (on EFS, once the file system notices), and the next server that starts takes over.

Logs

MockHub writes all of its logs to standard output, one line per event with a UTC timestamp, so the awslogs driver on Fargate sends them to CloudWatch with nothing to set up (the Terraform module already does this). You'll see:

  • startup, with the port, data folder and how sign-in works
  • every change from the audit log, as INFO audit
  • sign-ins, failed sign-ins (WARN) and refused requests with the reason
  • errors with their stack trace (ERROR)

To log every mock request too, add --verbose to WIREMOCK_OPTIONS. In CloudWatch Logs Insights, find who deleted something with:

fields @timestamp, @message
| filter @message like /INFO audit/ and @message like /Deleted/
| sort @timestamp desc
