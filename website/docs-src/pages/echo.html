An echo stub answers with the request it received, written as JSON. Point a client, a webhook or a proxy at it to see exactly what it sends: method, path, query, headers and body.

An echo server in one click

Install the Echo server — see what you send example from Examples in the sidebar. It becomes a project at /echo where every method and path answers with the request:

curl -X POST "http://localhost:8080/echo/orders/7?x=1&x=2" \
  -H 'Content-Type: application/json' -d '{"total": 12.5}'
{
  "method": "POST",
  "path": "/orders/7",
  "query": { "x": ["1", "2"] },
  "headers": { "Content-Type": "application/json", ... },
  "bodySize": 15,
  "body": "{\"total\": 12.5}",
  "json": { "total": 12.5 }
}

It also has a /echo/slow stub that answers after two seconds. Edit it, or add your own stubs beside it.

Echo in any stub

In the stub editor, choose Echo request as the response type. Set the status, and add headers if you need them. Delays, failure rates and every other response setting still apply. In JSON:

{
  "request": { "method": "ANY", "urlPattern": "/.*" },
  "response": { "status": 200, "transformers": ["mockhub-echo"] }
}
FieldWhat it holds
methodThe HTTP method.
pathThe path inside the project, without its base path.
queryQuery parameters; a parameter sent more than once becomes a list.
headersRequest headers, without the X-Forwarded-* and X-Real-IP headers a proxy adds.
bodySize, bodyThe body as text and its size in bytes.
jsonThe parsed body, when it is JSON.
formForm fields, when the body is application/x-www-form-urlencoded.

The answer is always application/json. Bodies over 1 MB get 413. Echo answers are recorded in the request log like any other call.
