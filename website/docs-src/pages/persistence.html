Stubs live in /data/mappings as WireMock JSON files. Projects live in /data/mockhub/projects.json, and response files in /data/__files. Request and callout history lives in /data/mockhub/history, one folder per project, with one file per hour. Snapshots live in /data/mockhub/snapshots, and gRPC descriptor sets in /data/mockhub/grpc. Back up the volume, or use Administration → Backup & restore.

There you tick whole organisations, single projects or a mix, and download them with their stubs as one JSON file. Users and sign-in settings are never included. To restore, open a backup file: MockHub lists what's inside and what each project would do here (new, replaces an existing project, or moves to a free base path). Pick the projects you want, the organisation to put them in, and whether existing projects are replaced or kept with a copy added beside them. The file restores into any MockHub.

Backups hold projects, stubs, files, saved data, gRPC descriptor sets and the datasets of the organisations they include. Restoring an organisation replaces its datasets with the file's; restoring projects into another organisation adds the datasets they need unless one with the same key is already there. Connections come along without their secrets; a restore keeps a secret already saved on this server. Backups don't hold request history: history is a record of traffic, kept for a few days, not something to restore. They don't hold snapshots either; download a snapshot as a file to keep a particular version.
