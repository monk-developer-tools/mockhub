By default, a call that no stub matches gets WireMock's 404 page, which lists the closest stubs and why each one missed. That's useful while you build a mock, but a real service answers unknown paths with its own error. In a project's Settings, turn on Default response to answer those calls your way.

  • Status: any code from 100 to 599. The default is 404.
  • Headers: one per line, Name: value.
  • Body: up to 1 MB. With Use templates on, the body can use every template helper, for example {{request.method}} {{request.path}}.
{
  "error": "No mock matches {{request.method}} {{request.path}}"
}

How it works

MockHub keeps the default response as a hidden stub with the lowest possible priority, so every one of your stubs is tried first. It doesn't show up in the stub list, the stub count or Postman and Bruno exports. A WireMock export includes it as a normal catch-all stub, so the same behaviour moves with the mappings. Calls answered by it still appear in the request log with Matched-Stub-Name: Default response.

A project that answers at the root only catches its own unmatched calls: paths under another project's base path still go to that project.
