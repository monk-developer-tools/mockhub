Browsers only let a web page call another origin when the answer carries CORS headers. MockHub adds them itself, per project, in Settings → Runtime behaviour → CORS:

SettingWhat browsers see
Server defaultFollows MOCKHUB_STUB_CORS (see configuration). By default any website can call the mock, with credentials: MockHub echoes the caller's Origin.
Allow listOnly the listed origins, for example https://app.example.com, a wildcard subdomain like https://*.example.com, or * for any. Choose the methods, the request headers (empty allows any) and whether cookies and credentials are allowed.
Fail on purposeNo CORS headers at all, so the browser blocks every call. Use it to see how your frontend shows a CORS error. Calls from servers, tests and curl still work, because only browsers enforce CORS.

Preflights

MockHub answers a preflight (OPTIONS with Origin and Access-Control-Request-Method) itself with 204, before stubs, API keys, IP rules or rate limits run, so your stubs don't need an OPTIONS stub. Browsers cache the answer for 30 minutes.

MockHub's own answers carry the CORS headers too: the 401 for a missing API key, the 403 from the IP allow list, the 429 from a rate limit and the default response. WireMock's own 404 for an unmatched call doesn't, so a browser reports it as a CORS error. Turn on a default response if your frontend needs to read that 404.
