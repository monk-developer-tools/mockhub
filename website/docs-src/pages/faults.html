• Fixed: always wait N ms.
  • Random range: uniform between two values.
  • Realistic: log-normal latency around a median, with a long tail.
  • Trickle: send the body in chunks over a period of time.
  • Faults: connection reset, empty response, malformed chunk, or random data then close.

A global delay for every response is on the Server page.

Random failures. Under Failures, make a share of calls fail, for example 10%, with an error status or a network fault. The rest get the normal response. Failed calls carry X-MockHub-Simulated-Error: true. Without a body of your own, REST stubs answer {"error":"Simulated failure"} and SOAP stubs answer a SOAP fault. In JSON, it's stored on the stub as:

"metadata": { "mockhub": { "errorRate": { "percent": 10, "status": 503 } } }
