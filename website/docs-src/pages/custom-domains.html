A project normally answers under its base path, like https://mocks.example.com/payments/charges/42. Give it a custom domain and the same stubs answer at the root of that host: https://payments.mocks.example.com/charges/42. Use it when a client can't add a path prefix, or when each team should have its own host.

Add a domain

Open the project's Settings, find Custom domains and enter one host name per line, up to 10. Anyone who can manage the project can change them. MockHub then checks the Host header of every mock request; when it matches, the request goes to this project as if the base path were in front of it.

RuleWhy
Host names onlyNo scheme, port, path or * wildcard. Names are stored in lowercase, and the port in the Host header is ignored.
One project per nameA name that another project already uses is refused, and the message names that project.
The base path keeps working/payments/... still answers on every host, so existing clients don't break.
The admin UI and API are not moved/__admin answers the same on every host.
gRPC is not affectedgRPC paths are already unprefixed and belong to one project.

Inside MockHub the request keeps its full path. The request log shows /payments/charges/42, and {{request.path}} in a template gives the same. Domains travel with the project in backups; a restored copy doesn't take names that another project already uses.

DNS and HTTPS

Point each name at the machine that runs MockHub, with an A record or a CNAME. A wildcard record such as *.mocks.example.com lets you add projects without touching DNS again. HTTPS stays with your reverse proxy, which needs a certificate for the names and must pass the original Host header on.

nginx

server {
  listen       443 ssl;
  server_name  mocks.example.com *.mocks.example.com;
  ssl_certificate     /etc/ssl/mocks/fullchain.pem;
  ssl_certificate_key /etc/ssl/mocks/privkey.pem;

  location / {
    proxy_pass         http://127.0.0.1:8080;
    proxy_set_header   Host $host;
    proxy_set_header   X-Forwarded-Proto $scheme;
    proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}

A wildcard certificate for *.mocks.example.com needs a DNS challenge, for example certbot certonly --dns-<provider> -d '*.mocks.example.com'. Or list each name on an ordinary certificate.

Caddy

mocks.example.com, payments.mocks.example.com, orders.mocks.example.com {
  reverse_proxy 127.0.0.1:8080
}

Caddy gets a certificate for each listed name and passes the Host header on by default.

Try it locally

curl -H 'Host: payments.mocks.example.com' http://localhost:8080/charges/42

Or add 127.0.0.1 payments.mocks.example.com to /etc/hosts and open http://payments.mocks.example.com:8080/charges/42.
