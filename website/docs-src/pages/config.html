Public tools

With MOCKHUB_PUBLIC_TOOLS=true, anyone can use these endpoints without signing in. They are off by default. When they are off, /__public/ is passed to your mocks like any other path.

EndpointWhat it does
ANY /__public/echo/**Answers with JSON that describes the request: method, path, query, headers, body, parsed JSON or form. Bodies up to 1 MB. Nothing is stored.
GET /__public/headersThe request headers
ANY /__public/status/{code}Answers with that status
ANY /__public/delay/{ms}Answers after the delay, up to 10,000 ms
POST /__public/binsCreates a webhook bin and returns its id and a private token
ANY /__public/bins/{id}/**Captured: the bin keeps the last 50 requests (bodies cut at 10 KB) and answers with its reply
GET /__public/inspect/{id}Lists captured requests; send the token as X-Bin-Token. Add ?after={seq} to get only newer ones. DELETE clears the bin.
GET|PUT /__public/inspect/{id}/responseReads or sets the bin's reply: {"status": 202, "contentType": "text/plain", "body": "ok"}, body up to 4 KB
POST /__public/renderRenders {"template": "...", "request": {"method", "url", "headers", "body"}} with the response-template engine and MockHub's helpers
POST /__public/fakeGenerates up to 100 records: {"count": 5, "fields": [{"name": "email", "expression": "Internet.emailAddress"}]}
POST /__public/mocksCreates an instant mock and returns its slug, a private token, its baseUrl and a skipped list. Send nothing for two sample stubs, or one of: {"stubs": [...]} with WireMock stub JSON; {"from": "openapi", "text": "..."} or {"from": "wsdl", "text": "..."} with a spec up to 500 KB (the first 20 operations); {"from": "records", "resource": "users", "records": [...]} with up to 50 records, served as a CRUD resource; {"from": "example", "id": "crud"}. Stubs from a spec or an example that instant mocks can't run are left out and listed in skipped.
GET /__public/mocks/examplesThe built-in examples that can start an instant mock
ANY /{slug}/**The mock answers like any MockHub project
GET|DELETE /__public/mocks/{slug}Describes or deletes the mock; send the token as X-Mock-Token
POST /__public/mocks/{slug}/stubs, PUT|DELETE …/stubs/{id}Adds, changes or removes a stub
GET /__public/mocks/{slug}/requestsThe last 50 requests to the mock

Limits per client address: 120 requests a minute in total, 30 renders or fake-data calls a minute, and 10 new bins or instant mocks an hour. Over the limit the answer is 429 with Retry-After. Bins are kept in memory and deleted 24 hours after their last request; the server holds at most 200.

The render endpoint turns off helpers that read the server (systemValue, hostname), partials and assign. It also caps loops at 2,000 runs in total, sizes and ranges at 10,000, rendering time at 2 seconds and output at 256 KB. Behind a reverse proxy, MockHub takes the client address from the last entry of X-Forwarded-For, the one your proxy adds, so a client can't choose its own. Set your proxy to add it (nginx: proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;), and don't expose MockHub directly when you rely on these limits.

Instant mocks are projects in a private organisation called "Instant mocks". The server holds at most 200. Each has up to 20 stubs, answers 1,000 requests a day, keeps up to 200 CRUD records of up to 4 KB each, and is deleted 7 days after its last change. Stubs and request bodies are limited to 64 KB. To keep one mock from slowing down the others, instant stubs can't proxy, call out, send webhooks, read files or use regex, XPath or JSON schema matching, and delays go up to 10 seconds. Response templates render with the same limits as the render endpoint and a 1-second budget.

When public tools are on, users whose server role is below admin can't see the "Instant mocks" organisation, and the native WireMock admin API (/__admin/mappings and the rest) is for admins only, because it lists the stubs of every project.
