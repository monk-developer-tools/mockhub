MockHub can send a trace, a log record and metrics for every request a mock answers to an OpenTelemetry collector, so mock traffic shows up next to the rest of your system in Grafana, Jaeger, Honeycomb, Datadog or any other OTLP backend. It is off until you set an endpoint.

Turn it on

Set the standard OpenTelemetry variables and restart MockHub:

OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4318
OTEL_SERVICE_NAME=mockhub
OTEL_EXPORTER_OTLP_HEADERS=x-api-key=…

MockHub sends OTLP over HTTP with JSON to /v1/traces, /v1/metrics and /v1/logs under the endpoint, which every OpenTelemetry collector accepts on port 4318. It does not speak gRPC or protobuf; if OTEL_EXPORTER_OTLP_PROTOCOL asks for one, it logs a warning and still sends JSON.

VariableWhat it does
OTEL_EXPORTER_OTLP_ENDPOINTBase URL of the collector. Off when empty
OTEL_EXPORTER_OTLP_TRACES_ENDPOINT, …_METRICS_ENDPOINT, …_LOGS_ENDPOINTFull URL for one signal, instead of the base URL
OTEL_TRACES_EXPORTER, OTEL_METRICS_EXPORTER, OTEL_LOGS_EXPORTERnone turns that signal off
OTEL_EXPORTER_OTLP_HEADERSHeaders for every export, as name=value,name2=value2, for an API key or a tenant
OTEL_SERVICE_NAME, OTEL_RESOURCE_ATTRIBUTESThe service name (default mockhub) and extra resource attributes such as deployment.environment=staging
OTEL_BSP_SCHEDULE_DELAYHow often spans and logs are sent, in ms (default 5000)
OTEL_METRIC_EXPORT_INTERVALHow often metrics are sent, in ms (default 60000)

What is sent

  • Traces: one server span per mock request, named method stub-name (or method unmatched), with http.request.method, url.path, url.query, http.response.status_code, client.address, mockhub.project.slug, mockhub.stub.name and mockhub.matched. A request with a W3C traceparent header becomes part of the caller's trace, so a mocked dependency appears inside your service's trace. 5xx answers are marked as errors.
  • Logs: one record per request, like POST /shop/orders → 201 in 12 ms, INFO for 2xx and 3xx, WARN for 4xx and ERROR for 5xx, with the same attributes and the span's trace and span ids.
  • Metrics: mockhub.requests, a cumulative counter, and http.server.request.duration, a histogram in seconds with the usual HTTP buckets, both split by method, status, project and whether a stub matched.

Request and response bodies and headers are not sent. Admin API calls are not exported, only mock traffic.

Delivery

Exports run on a background thread, so a slow or missing collector never slows a mock down. Up to 10,000 requests wait to be sent; past that, new ones are dropped rather than held in memory. When the collector can't be reached or answers with an error, MockHub logs a warning at most once a minute and carries on. When MockHub stops, it sends what is left.
