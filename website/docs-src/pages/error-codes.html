Most answers come from your stubs. The ones below come from MockHub itself, so you can tell a mock's answer from a problem with the setup. Every error body MockHub writes is JSON with an error message, except SOAP stubs, which get a SOAP fault.

From a mock URL

StatusWhenWhat to do
404No stub matched the request. WireMock answers Request was not matched with a diff against the closest stubs. Stubs that are turned off never match.Open the request log and pick the request: the closest stubs and the reason each one missed are listed. Turn the stub on, fix the matcher, or add a catch-all stub.
401The project needs an API key and the request has none (Missing API key) or a wrong one (Invalid API key). The JSON body names the header to send.Send the key in the header shown in the project settings. OPTIONS and ?wsdl requests don't need it.
Any status, with X-MockHub-Simulated-Error: trueThe stub's failure rate picked this call. The default body is {"error":"Simulated failure","status":…}, or a SOAP fault.Nothing, it's on purpose. Lower the rate or turn it off under the stub's Failures section.
Connection reset, empty reply or garbageThe stub's response is a fault, or its failure rate uses one.Expected when testing retries. Pick a status code instead if the client should get an answer.
502 with X-MockHub-Callout-Error: trueA wait-for-callout stub couldn't reach its target, timed out after 30 seconds, or rendered a broken template. The body is {"error":"Callout failed: …"}.Open the Callouts tab to see the request and the error. Private addresses are blocked unless MOCKHUB_CALLOUT_ALLOW_PRIVATE=true.
