Real APIs limit how often you can call them. To test how your service handles that, set a limit on the whole project in Settings → Runtime behaviour → Rate limit, or on one stub in the stub editor under Failures → Rate limit.

Limits count calls in a fixed window: per second, per minute or per hour, from 1 to 1,000,000 calls. A call over the limit gets 429 Too Many Requests with the headers real APIs send:

HTTP/1.1 429 Too Many Requests
Retry-After: 42
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 42
Content-Type: application/json

{"error":"Rate limit exceeded: 60 requests per minute. Try again in 42 s."}

Project and stub limits

The project limit counts every call under the base path, matched or not. A stub limit counts only the calls that stub answers, so you can make one endpoint stricter than the rest. When both are set, a call must pass both. Saving the project's runtime settings restarts its counters.

In stub JSON, a stub's limit is stored as:

"metadata": { "mockhub": { "rateLimit": { "requests": 5, "per": "minute" } } }

Counters live in memory, so a restart resets them, and each MockHub instance counts on its own if you run several.
