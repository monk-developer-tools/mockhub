Make a stub answer like a real API when the request is wrong: a missing field, an e-mail that isn't one, an id that isn't a UUID. Put validation helpers at the start of a templated response body. When a rule fails, MockHub answers 400 (or the status you choose) with a JSON message instead of the normal response:

{{required (jsonPath request.body '$.name') 'name is required'}}
{{isEmail (jsonPath request.body '$.email') 'Enter a valid e-mail'}}
{{check (matches (jsonPath request.body '$.code') '^[A-Z]{3}$') 'code must be three capital letters' status=422}}
{ "id": "{{randomValue type='UUID'}}", "name": "{{jsonPath request.body '$.name'}}" }

A call without a name gets:

HTTP/1.1 400 Bad Request
Content-Type: application/json

{"error":"name is required","status":400}

Helpers

HelperFails when
{{required value 'message'}}the value is missing or blank
{{isEmail value 'message'}}it isn't an e-mail address
{{isUuid value 'message'}}it isn't a UUID
{{isNumber value 'message'}}it isn't a number
{{check condition 'message'}}the condition is false; use it with matches, eq, gt, and and the other comparison helpers

Add status=422 (any status from 400 to 599) to any of them. Rules run in order and the first one that fails answers. Without a message, isEmail, isUuid and isNumber just answer true or false, for use in {{#if}}. Validation works in responses only, not in webhook bodies.

To validate against a schema, or to match only valid requests, use request matching instead: a stub that doesn't match lets a more general one, such as a 400 stub, answer.
