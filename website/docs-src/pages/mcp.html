MockHub is an MCP server, so AI agents such as Claude Code, Cursor, Codex and Claude Desktop can read and build your mocks. The agent works through the same rules as the UI: the same validation, your roles and the token's limits. Every change it makes is in the audit log as “Alex Morgan via token “Claude Code””.

The server is at /__admin/mockhub/mcp and speaks Streamable HTTP. Connect with a personal access token; with sign-in off, no token is needed.

Connect an agent

Create a token under Account → Access tokens. MockHub shows these snippets with your URL and token filled in. Replace $HUB with your MockHub address, such as https://mockhub.example.com.

Claude Code

claude mcp add --transport http mockhub $HUB/__admin/mockhub/mcp \
  --header "Authorization: Bearer mh_…"

Cursor, in .cursor/mcp.json or ~/.cursor/mcp.json

{
  "mcpServers": {
    "mockhub": {
      "url": "$HUB/__admin/mockhub/mcp",
      "headers": { "Authorization": "Bearer mh_…" }
    }
  }
}

Codex, in ~/.codex/config.toml, with the token in the MOCKHUB_TOKEN environment variable

[mcp_servers.mockhub]
url = "$HUB/__admin/mockhub/mcp"
bearer_token_env_var = "MOCKHUB_TOKEN"

Claude Desktop, in claude_desktop_config.json, through the mcp-remote bridge (needs Node.js)

{
  "mcpServers": {
    "mockhub": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "$HUB/__admin/mockhub/mcp",
               "--header", "Authorization: Bearer mh_…"]
    }
  }
}

Any other client that supports Streamable HTTP works the same way: the URL plus an Authorization header. MockHub answers each call with plain JSON and keeps no session, so it works behind any load balancer.

Things to ask

  • “In the Bookshop project, add GET /books/{id} that returns 404 for id 0 and a book with that id otherwise.”
  • “Which requests to Checkout found no stub in the last hour? Create stubs for them.”
  • “Build a CRUD resource for /customers with 10 realistic customers.”
  • “Make every call to Payments 1.5 seconds slower and fail 5% of them with a 503.”
  • “After POST /payments, call the callbackUrl from the request 2 seconds later with status SETTLED.”
  • “Why is my webhook failing? Look at the recent callouts.”
  • “Read openapi.yaml in this repo and mock every endpoint our service calls.”
  • “Clear the request history, then run the tests and show me what didn't match.”
  • “Take a snapshot of Checkout, add the retry stubs, and restore it if the tests fail.”

An agent with your code open is useful: it can read the client code or the contract, create the stubs, run your tests against the mock and fix what missed.

Tools

Each tool takes a project, which can be its id, slug, name or base path.

AreaTools
Projectslist_projects, get_project (with its mock URL and runtime behaviour)
Stubslist_stubs (in matching order), get_stub, create_stub, update_stub, delete_stub, set_stub_enabled, reorder_stubs
Referenceget_stub_reference: how to write matching, templating, delays, faults, state, webhooks and SOAP in MockHub, so the agent gets it right first time
Runtimeget_runtime, set_runtime: delays, failure rates, rate limits, default response, CORS and the other project-wide behaviour
Requestssearch_requests (text, method, status, unmatched only, stub, header, last N minutes), get_request, clear_requests
Calloutslist_callouts: recent webhooks and forwards with their results
Datacreate_crud_resource, list_data, list_records, save_record, delete_record

Read-only tools are marked as such, and deleting tools as destructive, so clients that ask before risky calls can do so. Request bodies and callout answers come from outside callers; MockHub tells the agent to treat them as data, not instructions.

Review mode

A token set to Stage for review can read everything in its scope, but its stub, runtime, snapshot and restore changes don't go live. They wait in the project's Assistant tab under Changes from agents, with the token name and time, and an editor applies or discards each one after looking at the JSON or the diff. This works even when the AI assistant is off. Other changes, such as clearing requests, saving records or pulling from another project, are refused for review tokens, and so is the REST API. Use review mode for agents you're trying out, or for shared projects where a person should see every change first.

Security

  • The token decides what the agent can do: no more than your own access, limited to its projects and its role.
  • Requests from a browser page on another site are refused (the Origin must match the host), so a web page can't drive your agent's session.
  • Revoke a token to cut an agent off at once. The audit log shows what each token changed.
