Set MockHub as the proxy of a browser, an app, a phone or a test run. Calls that match a stub in the chosen project get the mock answer. Every other call goes on to the real service, and all of them are recorded in that project, so you can turn any real answer into a stub with one click. HTTPS works too: MockHub reads it with its own certificate authority (CA), which you trust on the client.

Turn it on

docker run -p 8080:8080 -e MOCKHUB_PROXY=true -v mockhub-data:/data mockhub/mockhub

The proxy uses the main port, so the client's proxy is http://<mockhub-host>:8080. Then, as an admin, open Server, find Forward proxy and choose the project for proxied traffic. Until you do, proxied calls get 503.

RuleWhy
Only trusted networksBy default only loopback and private addresses (10.x, 172.16–31.x, 192.168.x, fc00::/7) may use the proxy; others get 403. Set MOCKHUB_PROXY_ALLOW to a comma-separated list of addresses or CIDR ranges to change it. Don't open the proxy to the internet.
Connect to MockHub directlyA reverse proxy such as nginx in front of MockHub doesn't pass proxy requests on. Give clients MockHub's own port, for example on your LAN or through a VPN.
Stubs match the path, any hostA proxied call to https://api.example.com/users/42 is matched as /users/42 in the chosen project. To mock only one host, add a Host header rule to the stub.
The CA stays the sameMockHub creates it on first start and keeps it in /data/mockhub/proxy, so clients trust it once.

In the request log, proxied calls show with the project's base path in front, like /captured/users/42. Open one and choose Create stub from this request to mock it from then on.

Trust the CA certificate

Download it from Server → Forward proxy → Download CA certificate, or without signing in:

curl -o mockhub-proxy-ca.pem http://<mockhub-host>:8080/__admin/mockhub/api/proxy/ca.pem

Anyone who has the CA's private key could read the traffic of a device that trusts it. Trust it only on test devices and remove it when you're done.

curl and command-line tools

curl -x http://localhost:8080 --cacert mockhub-proxy-ca.pem https://api.example.com/users/42

export HTTP_PROXY=http://localhost:8080 HTTPS_PROXY=http://localhost:8080

Most tools read HTTP_PROXY and HTTPS_PROXY. Node.js needs NODE_EXTRA_CA_CERTS=mockhub-proxy-ca.pem, Python requests REQUESTS_CA_BUNDLE, and Java the CA imported with keytool -importcert -alias mockhub -file mockhub-proxy-ca.pem -keystore truststore.jks plus -Dhttps.proxyHost=localhost -Dhttps.proxyPort=8080.

Browsers

  • Firefox: Settings → Network Settings → Manual proxy configuration, HTTP proxy localhost port 8080, and tick "Also use this proxy for HTTPS". Import the CA under Settings → Privacy & Security → Certificates → View Certificates → Authorities, and trust it to identify websites. Firefox keeps its own trust store, so this doesn't touch the rest of the system.
  • Chrome and Edge use the system proxy and trust store; set them up as for macOS or Windows. To keep it separate, start a profile with --proxy-server=http://localhost:8080.

macOS

  1. System Settings → Network → your network → Details → Proxies: turn on Web proxy (HTTP) and Secure web proxy (HTTPS), both localhost port 8080.
  2. Double-click mockhub-proxy-ca.pem to add it to Keychain Access, open it, and under Trust set "When using this certificate" to Always Trust.

Android

  1. Settings → Network → Wi-Fi → your network → Edit → Advanced → Proxy: Manual, host the computer running MockHub, port 8080. Phone and computer must be on the same network, and the phone's address must be allowed by MOCKHUB_PROXY_ALLOW (private networks are by default).
  2. Copy mockhub-proxy-ca.pem to the phone and install it under Settings → Security → Encryption & credentials → Install a certificate → CA certificate.
  3. Browsers then trust it. Apps on Android 7 and later trust user-installed CAs only when their network_security_config allows it, which you can add to debug builds of your own app:
<network-security-config>
  <debug-overrides>
    <trust-anchors><certificates src="user" /></trust-anchors>
  </debug-overrides>
</network-security-config>

Apps that pin certificates don't accept any proxy CA.
