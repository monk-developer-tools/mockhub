A dataset is a table of test data, such as customers, products or bank accounts, that every project in an organisation can read. Upload it once as CSV or JSON, then answer from it in any stub: GET /customers/42 returns customer 42 from the dataset instead of a hand-written body.

Create and upload

Open Datasets in the sidebar and choose New dataset. Give it:

SettingWhat it does
KeyThe name stubs use, e.g. customers. Lowercase letters, digits, dashes and underscores; it can't change later.
Identity fieldsUp to 3 fields that tell records apart, usually id. Uploads use them to update or skip records, and two records can't share the same values.
Indexed fieldsUp to 5 fields you look records up by, such as email. Lookups on them stay fast in big datasets; other fields work too, just slower.

Then Upload a file. MockHub reads:

  • CSV: the first line names the columns. Numbers and true/false are recognised by themselves; values with a leading zero such as 01234 stay text. Force a type with a suffix: zip:string, price:number, active:boolean or tags:json. Quoted values can hold commas, quotes and line breaks.
  • JSON: an array of objects, [{"id": 1, "name": "Ada"}].
  • NDJSON: one object per line.

When the dataset already has records, choose what happens:

ModeRecords with the same identityNew records
Replace allThe file becomes the whole dataset.
Update and addreplaced by the file'sadded
Add onlykept; the file's are skippedadded

A mistake is reported with its line, e.g. Line 7 has 5 values but the header has 4 columns, and nothing is changed.

Answer from a dataset

Turn on templating in the stub and use the dataset helpers. Each takes the dataset key and up to three field=value filters; a record matches when every filter matches.

{{{dataset-one 'customers' id=request.path.id}}}

gives one record as JSON. Read single fields with #with, which also handles "not found":

{{#with (dataset-one 'customers' id=request.path.id)}}
  {"name": "{{name}}", "city": "{{address.city}}"}
{{else}}
  {"error": "No customer {{request.path.id}}"}
{{/with}}

dataset gives a list, up to 100 records unless you set limit (at most 1,000):

{{{dataset 'products' category=request.query.category limit=20}}}
{{#each (dataset 'orders' status='open')}}{{id}} {{/each}}
{{len (dataset 'orders' status='open')}}

Matching follows the values, not their spelling: id=7 finds the number 7 and 7.0, and active=TRUE finds true. Text matches exactly, so 007 doesn't find the number 7. Filters on a list field match any item, and address.city reaches into nested objects. The helper reference and the Insert dynamic value picker have these ready to copy.

The helpers read the datasets of the organisation the stub's project belongs to. They work in response bodies and headers, not in webhooks.

Browse and try lookups

The Datasets page shows each dataset's columns and types, and lets you search and page through records. Use it in a stub lists helpers for that dataset to copy, and Try a lookup shows exactly what dataset-one or dataset returns for the filters you enter.

Turn a stub's body into a dataset

When a stub answers with a JSON list, such as one made by an OpenAPI import, choose Edit as table under the body. Edit cells, add or remove rows and columns; values keep their column's type. Then either use the result as the body, or choose Move the rows to a dataset: MockHub creates the dataset from the rows and replaces the body with a helper. A path like /pets/{petId} gets dataset-one by petId; other paths get the whole list. A body that wraps the list, like {"data": [...], "total": 2}, keeps its wrapper.

Who can change them, and limits

Everyone in the organisation can browse its datasets. Changing them needs the editor role on the organisation itself, not just on a team. An upload can be up to 20 MB; a dataset holds up to 100,000 records of up to 64 KB each, and an organisation up to 100 datasets.

Datasets are saved on disk in /data/mockhub/datasets, go into backups with their organisation, and are deleted with it.
