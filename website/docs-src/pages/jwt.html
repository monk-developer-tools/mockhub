Mock an OAuth or OpenID provider, or any API that hands out and reads JSON Web Tokens. MockHub signs real tokens your client libraries accept, publishes the public key as a JWKS, and reads claims from incoming bearer tokens. Turn on Response templating for the stub; Insert dynamic value → JWT & OAuth has every helper ready to insert.

Sign a token

{
  "access_token": "{{jwt sub=(jsonPath request.body '$.username') scope='read write' expiresIn=3600}}",
  "token_type": "Bearer",
  "expires_in": 3600
}
OptionWhat it does
any name=valuebecomes a claim: sub, scope, aud, iss, roles…
claims=(parseJson …)adds every field of a JSON object as claims
expiresInseconds until exp; default 3600. iat is always now
algRS256 (default), signed with this server's private key, or HS256 with secret='…'

MockHub creates a 2048-bit RSA key the first time it signs a token and keeps it in /data/mockhub/jwt-key.json, so tokens and keys stay valid across restarts. RS256 tokens carry the key's kid. The key is only for test tokens: never reuse it for anything real. It isn't part of backups or snapshots, so a new server has a new key.

Publish the public key

Add a stub for GET /.well-known/jwks.json with the body {{{jwks}}} (triple braces keep the JSON as is). Point your service's JWKS or issuer setting at it and it verifies MockHub's RS256 tokens like real ones. The stub editor's template gallery has OAuth token endpoint and JWKS public keys ready to add.

Read the caller's token

{{check request.headers.Authorization 'Send a bearer token' status=401}}
{
  "user": "{{jwtDecode request.headers.Authorization 'sub'}}",
  "claims": {{{json (jwtDecode request.headers.Authorization)}}}
}

jwtDecode takes a token, with or without Bearer in front. With a claim name it gives that claim; without one it gives every claim, ready for json, lookup or #with. It doesn't check the signature or expiry: a mock reads what it's given. To refuse calls without a token, use check as above.
