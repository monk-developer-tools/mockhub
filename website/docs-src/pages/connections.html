Callouts and proxies often call a real service that wants a token: a bank sandbox behind OAuth2, or a maps API with a key header. A connection holds that secret once for the whole organisation. A stub names the connection and MockHub sends the header for you, so no secret sits in a stub, an export or the request log.

Add a connection

Open Connections in the sidebar and choose New connection. Only managers of the organisation can add, change, test or delete connections; everyone in it can see which exist.

OAuth2 client credentialstoken URL, client id, client secret, optional scope and audienceAuthorization: Bearer <token>

The header name and value prefix can be changed for both, e.g. Authorization with prefix Token . For OAuth2, MockHub sends the client id and secret in a Basic auth header (or in the form body if the service wants that), keeps the token until 30 seconds before it expires and then fetches a new one. The token URL may be a path on this MockHub, which helps when you mock the identity provider too.

Test fetches a fresh token and shows a masked preview, how long it lasts and its scope, or the token endpoint's error.

How secrets are kept

Secrets are encrypted with AES-256-GCM before they're written to disk and are never sent back to the browser; leave the secret empty when you edit a connection to keep the saved one. The key comes from MOCKHUB_SECRET_KEY. Without it, MockHub creates a random key in mockhub/secret.key inside the data folder. Keep that file, or set the variable, or saved secrets can't be read after a move.

Backups include connections without their secrets. Restoring keeps the secret of a connection that's already there; a new one needs its secret entered again.

Use one in a callout

In a webhook or a wait-for-callout, pick the connection under Sign with. In JSON it's connection:

"serveEventListeners": [{
  "name": "mockhub-callout",
  "parameters": {
    "method": "POST",
    "url": "https://sandbox.bank.example/payments/{{jsonPath originalRequest.body '$.id'}}/confirm",
    "connection": "bank",
    "retry": { "count": 3 }
  }
}]

The header replaces one of the same name in the stub. The Callouts tab shows it as ••• (connection bank), never the token. If the connection is missing or the token can't be fetched, the callout isn't sent and its entry says why, e.g. Connection bank: There is no connection called bank in this organisation.

Retries

A callout can try again when the target answers 429 or 5xx, or can't be reached. Set Retries (up to 5) and the First wait, which doubles before each further try and is capped at 30 seconds:

"retry": { "count": 3, "backoffMs": 500, "statuses": "429,503" }

statuses is optional and takes codes and classes such as 5xx. Every attempt is its own entry in the Callouts tab with its attempt number. A webhook waits between tries in the background; a wait-for-callout keeps the caller waiting until the last try.

Use one on a proxy

On a stub that proxies to a real service, pick the connection under Sign with. In JSON:

"response": {
  "proxyBaseUrl": "https://sandbox.bank.example",
  "transformers": ["mockhub-connection"],
  "transformerParameters": { "connection": "bank" }
}

Each proxied request gets the header once, replacing one the caller sent. Other additionalProxyRequestHeaders stay as they are. If the token can't be fetched the caller gets 502 with the reason.
