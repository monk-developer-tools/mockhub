Use cases

          
Where teams use MockHub.

          
The same server covers the whole path from a developer's laptop to a shared test environment.

        

        

        
        

          
          
Test environments without the real services

          
Give every dependency its own mock URL in QA and CI. Tests stop failing because another team's service is down or out of data.

          How projects and base paths work
        

        

          
          
Frontend work before the backend exists

          
Import the OpenAPI contract and build against realistic answers on day one, with fake data and CRUD resources that remember.

          Import a contract
        

        

          
          
Partner APIs and their webhooks

          
Mock the payment provider and its callbacks: answer at once, then call your service back, or wait for a partner's reply.

          Webhooks and callouts
        

        

          
          
Failure and resilience testing

          
Slow answers, dropped connections and a failure rate per stub, so you can prove timeouts and retries before production does.

          Delays and faults
        

        

          
          
One home for scattered WireMock mocks

          
Move every team's mappings into one server with a UI, sign-in and an audit log, and keep every URL they call today.

Demos and training that never break

Built on WireMock.
Made for teams.

          
Everything WireMock can do, organised into projects, editable by anyone, and safe across restarts.

        


        

          

            
One URL per service.

            
Each project lives under its own base path. Point your service at it and leave the real dependency out of your tests.

            

              
GET/payment-service/payments/{id}200

              
POST/payment-service/refunds201

              
POST/legacy-crm/ws/customers500

              
DELETE/orders/items/{id}401

            

          


          

            0
            
Lost mocks after a restart.

            
Every stub is written to disk, including ones created through the native WireMock API.

          


          

            
Dynamic responses.

            
Echo path variables, read the body, and generate IDs and dates with Handlebars.

            
{ "id": "{{request.path.id}}",
  "at": "{{now}}" }

          


          

            
Stateful flows.

            
The same call answers differently as state changes.

            
    
              
  1. Started
    2. 
              
  2. Item added
    3. 
              
  3. Checked out
    4. 
            

          


          

            
Chaos on demand.

            
Delays, random latency, dropped connections and 503s to prove your retries work.

            
          


          

            
Fast for people who live on the keyboard.

Start from contracts.

            
Import an OpenAPI or Swagger spec, a WSDL, WireMock mappings or a whole WireMock folder, and get working stubs in one step.

            

              YAMLopenapi.yaml
              WSDLbilling.wsdl
              JSONmappings.json
              ZIPwiremock.zip
            

          


          

            
A playground that remembers.

            
Call your mocks or any public API, keep every request in your history, and turn a real response into a stub in one click.

            

              GETapi.example.com/users200 · 84 ms
            

          


          

            
Data that looks real.

            
Generate 20 customers, products or orders with names, e-mails, addresses and prices, in dozens of languages.

            
[{ "id": 1, "name": "Priya Raman",
   "email": "priya.raman@example.com",
   "address": { "city": "Leeds" } }, …]

          


          

            
Webhooks that call back.

            
After a stub answers, call your service back, forward the request to a partner, or wait for the partner's reply. Every call is logged with what was sent and what came back.

            

              
POSTpartner.example.com/callbacks204

              
POSTissuer.example.com/authorize201

            

          


          

            
Insert a dynamic value.

            
Search 180 helpers for request fields, dates, maths, arrays, state and fake data, and drop one in at the cursor.

            
{ "ref": "{{jsonPath originalRequest.body '$.ref'}}",
  "email": "{{fake 'Internet.emailAddress'}}" }

          

        

      

    


    

      

        

          
AI assistant

          
Describe it. Review it. Ship it.

          
Tell the assistant what you need, or paste an OpenAPI spec. It reads your stubs and request log, drafts the changes, and shows each one as a diff. Nothing goes live until someone with the editor role applies it.

        

        

          
        

        

          OpenRouter
          Hugging Face
          LiteLLM proxy
          Any OpenAI-compatible API
        

        
Bring your own model and key. Your conversation goes only to the provider you choose.

Your mocks, in their favourite client.

          
Export any project as a Postman or Bruno collection. Every request is ready to send, with a status check included, and one baseUrl switches between the mock and the real service.

        

        

          

            
Postman

            
Collection v2.1, grouped into folders, with path variables filled in.

            
pm.test("Status is 201", () =>
  pm.response.to.have.status(201));

          

          

            
Bruno

            
Plain .bru files with a MockHub environment, ready to commit next to your code.

            
post {
  url: {{baseUrl}}/pets
}
assert { res.status: eq 201 }

          

        

      

    


    

      

        

          
Don't take our word for it.
Call it.

          
The live demo is running right now with the example projects installed. Paste any of these into a terminal.

        

        

          
Terminal

          
# a path template that echoes the id
curl https://mockhub.devops-monk.com/example-petstore/pets/42

# JSON body matching: a valid pet gets 201, anything else 400
curl -X POST https://mockhub.devops-monk.com/example-petstore/pets \
  -H 'Content-Type: application/json' -d '{"name":"Rex","type":"dog"}'

# a SOAP operation matched on XPath values: 2 + 3 = 5
curl https://mockhub.devops-monk.com/example-soap/ws/calculator -H 'Content-Type: text/xml' \
  -d '<s:Envelope xmlns:s="http://schemas.xmlsoap.org/soap/envelope/"><s:Body><Add xmlns="http://example.com/calculator"><a>2</a><b>3</b></Add></s:Body></s:Envelope>'

# fails once with 503, then recovers: test your retries
curl -i https://mockhub.devops-monk.com/example-chaos/flaky

Runs wherever your tests do.

          
A single JAR in a 115 MB distroless image. Non-root, configured with environment variables, with a built-in health check.

        

        

          

            
            
            
            
          

          

            
docker run -d --name mockhub -p 8080:8080 \
  -v mockhub-data:/data \
  -e MOCKHUB_PUBLIC_URL=https://mocks.acme.internal \
  -e MOCKHUB_USERS="lead:s3cret:admin,qa:qa-pass:editor" \
  abhaypratap/mockhub

          

          

            
services:
  mockhub:
    image: abhaypratap/mockhub
    ports: ["8080:8080"]
    volumes: ["mockhub-data:/data"]
    restart: unless-stopped
volumes:
  mockhub-data:

          

          

            
module "mockhub" {
  source = "git::https://github.com/monk-developer-tools/mockhub.git//deploy/terraform"

  region                   = "eu-west-1"
  vpc_id                   = module.vpc.vpc_id
  load_balancer_subnet_ids = module.vpc.private_subnets
  service_subnet_ids       = module.vpc.private_subnets
  certificate_arn          = aws_acm_certificate.mocks.arn
}

            
Fargate, EFS-backed persistence, an ALB with HTTPS, and IAM, all covered by terraform test.

          

          

            
MOCKHUB_DATA_DIR=./mockhub-data java -jar mockhub.jar
