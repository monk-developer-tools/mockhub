MockHub

Every dependency. Mocked in minutes.

A self-hosted mock server for REST and SOAP that the whole team can use. Give each service its own URL, edit stubs in a real UI, and hand developers a Postman or Bruno collection that already works.

Built on WireMock. Made for teams.

Everything WireMock can do, organised into projects, editable by anyone, and safe across restarts.

One URL per service.

Each project lives under its own base path. Point your service's config at it, and leave the real dependency out of your test environment.

GET/payment-service/payments/{id}200
POST/payment-service/refunds201
POST/legacy-crm/ws/customers500
DELETE/orders/items/{id}401
0

Lost mocks after a restart.

Every stub is written to disk, including ones created through the native WireMock API. Mount a volume and redeploy with confidence.

Dynamic responses.

Echo path variables, read the JSON body, generate IDs and dates with Handlebars templating.

{ "id": "{{request.path.id}}",
  "at": "{{now}}" }

Stateful flows.

Scenarios let the same call answer differently as state changes: empty cart, item added, checked out.

Chaos on demand.

Delays, random latency, dropped connections and 503s to prove your timeouts and retries actually work.

Fast for people who live on the keyboard.

Press ⌘K to jump to any project or stub. N adds a stub, / searches, and ⌘S saves. Every stub and every logged request can be copied as cURL, HTTPie, JavaScript, Python or Java.

See problems before your tests do.

Each project shows traffic for the last hour and counts requests that matched no stub. One click takes you to the closest stub and turns the request into a new one.

Try it without leaving the editor.

Send a real request to the stub you're editing and see status, headers, body and timing. A live request log shows every call, with the closest stub for anything that didn't match.

Start from contracts.

Import an OpenAPI or Swagger spec, a WSDL, or existing WireMock mappings, and get working stubs with realistic sample data in one step.

Don't take our word for it. Call it.

The live demo is running right now with the example projects installed. Paste any of these into a terminal.

# a path template that echoes the id
curl https://mockhub.devops-monk.com/example-petstore/pets/42

# JSON body matching: a valid pet gets 201, anything else 400
curl -X POST https://mockhub.devops-monk.com/example-petstore/pets \
  -H 'Content-Type: application/json' -d '{"name":"Rex","type":"dog"}'

# a SOAP operation matched on XPath values: 2 + 3 = 5
curl https://mockhub.devops-monk.com/example-soap/ws/calculator -H 'Content-Type: text/xml' \
  -d '<s:Envelope xmlns:s="http://schemas.xmlsoap.org/soap/envelope/"><s:Body><Add xmlns="http://example.com/calculator"><a>2</a><b>3</b></Add></s:Body></s:Envelope>'

# fails once with 503, then recovers: test your retries
curl -i https://mockhub.devops-monk.com/example-chaos/flaky

Everything about a service, on one screen.

Each project opens on an overview: its mock URL, a snippet to connect your app, last-hour traffic, requests that found no stub, and one-click Postman and Bruno exports.

  • Connect snippets for env vars, Spring, Docker Compose and cURL
  • A getting-started checklist for new projects
  • Unmatched requests flagged before they turn into failing tests

SOAP is a first-class citizen.

Drop in a WSDL and MockHub creates one stub per operation, with request and response envelopes generated from the schema.

  • Matches on the operation inside soap:Body, or on any field value with XPath
  • SOAP 1.1 and 1.2, envelope and fault helpers
  • ?wsdl served with its address pointing at the mock
  • A clear SOAP fault for operations you haven't mocked yet

Your mocks, in their favourite client.

Export any project as a Postman collection or a Bruno collection. Every request is ready to send, with a status check included. One baseUrl variable switches between the mock and the real service.

Postman

Collection v2.1, grouped into folders, path variables filled in, and a test that checks the expected status.

pm.test("Status is 201", () =>
  pm.response.to.have.status(201));

Bruno

A zip of plain .bru files with a MockHub environment. Unzip it, open the collection, and commit it next to your code.

post {
  url: {{baseUrl}}/pets
  body: json
}
assert { res.status: eq 201 }

From zero to mocked in three steps.

Run it

One container, one port. Data goes to /data.

docker run -p 8080:8080 \
  -v mockhub-data:/data \
  abhaypratap/mockhub

Create a project

In the UI, or straight from your CI pipeline.

curl -X POST localhost:8080/__admin/mockhub/api/projects \
  -d '{"name":"Payment service"}'

Point your service at it

Swap the dependency's URL for the project's mock URL.

PAYMENT_API_URL=http://mockhub:8080/payment-service

Runs wherever your tests do.

A single JAR in a 115 MB distroless image for amd64 and arm64. It runs as non-root, is configured through environment variables, and has a built-in health check.

docker run -d --name mockhub -p 8080:8080 \
  -v mockhub-data:/data \
  -e MOCKHUB_PUBLIC_URL=https://mocks.acme.internal \
  -e MOCKHUB_USERS="lead:s3cret:admin,qa:qa-pass:editor" \
  abhaypratap/mockhub
services:
  mockhub:
    image: abhaypratap/mockhub
    ports: ["8080:8080"]
    volumes: ["mockhub-data:/data"]
    restart: unless-stopped
volumes:
  mockhub-data:
module "mockhub" {
  source = "git::https://github.com/monk-developer-tools/mockhub.git//deploy/terraform"

  region                   = "eu-west-1"
  vpc_id                   = module.vpc.vpc_id
  load_balancer_subnet_ids = module.vpc.private_subnets
  service_subnet_ids       = module.vpc.private_subnets
  certificate_arn          = aws_acm_certificate.mocks.arn
}

Fargate, EFS-backed persistence, an ALB with HTTPS, and IAM, all covered by terraform test.

MOCKHUB_DATA_DIR=./mockhub-data java -jar mockhub.jar
